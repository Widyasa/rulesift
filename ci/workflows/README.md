# Staged GitHub Actions workflows

These files belong in `.github/workflows/`. They are kept here because the
token that prepared the release work had no `workflow` scope (GitHub refuses
pushes that touch `.github/workflows/` without it), and Actions is currently
disabled on the repository.

| File | Task | What it does |
|---|---|---|
| `ci.yml` | W1-T2 (#4) | fmt, clippy `-D warnings`, tests on Ubuntu, macOS, Windows |
| `self-test.yml` | W5-T4 (#37) | Runs this repo's composite action from source on every PR |
| `fp-check.yml` | W6-T3 (#44) | Weekly and manual false-positive check (`scripts/fp-check.sh`) |
| `release.yml` | W6-T4 (#45) | Generated by `dist generate` (cargo-dist 0.33.1). Runs only on a pushed version tag, plus `dist plan` on PRs |
| `wheels.yml` | W6-T5 (#46) | maturin wheels and sdist with a fresh-venv smoke test. No upload |
| `rulesift.yml` | W6-T7 (#48) | Dogfooding: RuleSift checks this repo's agent files and `rulesift.lock` |

To activate them (Widya):

```sh
gh auth refresh -h github.com -s workflow
git switch -c ci/activate-workflows origin/master
mkdir -p .github/workflows
git mv ci/workflows/*.yml .github/workflows/
git rm -q ci/workflows/README.md
dist plan            # must not report release.yml as out of date
git commit -m "ci: activate staged workflows" && git push -u origin HEAD
```

Then re-enable Actions and open the PR. Its own run of `ci.yml` and
`self-test.yml` closes the loop for W1-T2 and W5-T4.

`release.yml` needs two repository secrets before the first tag:

- `HOMEBREW_TAP_TOKEN`: push access to `Widyasa/homebrew-tap`.
- `NPM_TOKEN`: an npm automation token for the `rulesift` package.

See `docs/release-checklist.md`.
